# gathering 모임장의 모임 관리와 열기 중복 방지 규칙

`architecture` 스킬의 하위 문서다. 언제 읽는지는 `SKILL.md`의 하위 문서 표를 참고한다. 모임의 기본 모델과 정산 규칙은 `gathering.md`에 있다. 근거, 택하지 않은 안, 재검토 조건은 `docs/decisions/gathering.md`에 있다.

## 모임 열기의 중복 방지

- 모임 열기 요청은 클라이언트가 만든 요청 id(`clientRequestId`, UUID)를 필수로 담는다.
- 같은 모임장이 같은 요청 id로 다시 보내면 모임을 새로 만들지 않고 처음 연 모임에 참여 토큰을 새로 발급해 201로 돌려준다. 기존 참여 토큰은 무효가 된다. 요청 내용이 달라도 처음 모임을 돌려주고, 이때 페어링은 저장하지 않는다.
- 요청 id는 `gathering`의 `(host_member_id, client_request_id)` unique 제약과 `ON CONFLICT DO NOTHING`으로 가린다. 동시에 같은 요청이 오면 늦은 요청은 먼저 넣은 요청이 커밋한 뒤 409(`GATHERING_OPEN_CONFLICT`)로 거절한다. 참여 토큰을 새로 발급하면 먼저 응답받는 요청의 토큰이 무효가 되기 때문이다.
- 지운 모임의 행은 없으므로 같은 요청 id로 다시 열면 새 모임을 만든다.

## 모임장의 모임 관리

- 모임을 만든 회원은 JWT로 인증해 자기 모임 목록 조회(`GET /gatherings`), 이름 수정(`PATCH /gatherings/{gatheringId}`), 삭제(`DELETE /gatherings/{gatheringId}`)를 할 수 있다. `*Api`는 `GatheringApi`다.
- 목록은 파기 시각이 지난 모임을 담지 않고 id가 큰 순서(최근에 연 순서)로 돌려준다. 모임의 id, 이름, 연 시각, 기록 기간이 끝나는 시각, 연장 여부, 파기 예정 시각(`deletesAt`), 참여자 수를 담는다. 참여자는 복호화하지 않고 수만 센다. 페이지로 나누지 않는다.
- 이름은 모임 열기와 같은 규칙(공백만 있으면 안 되고 50자까지)이다. 기록 기간과 관계없이 고칠 수 있고, 성공하면 204다. 파기 시각이 지난 모임은 404(`GATHERING_NOT_FOUND`), 모임을 만든 회원이 아니면 403(`NOT_GATHERING_HOST`)이다.
- 모임 이름은 모임을 저장해도 바뀌지 않고 전용 쿼리(`updateName`)로만 바꾼다. 참여나 차수 추가가 메모리에 있던 옛 이름으로 덮어쓰지 않게 하기 위해서다.
- 삭제는 파기 시각 전에 모임을 지운다. `DeleteGatheringService`(`@CommandService`)가 한 트랜잭션에서 모임과 정산 건을 잠그고 모임장과 보낸 분담금을 확인한 뒤 데이터 키를 지우고, 파기와 같은 순서로 나머지 행을 지운다. 중간에 실패하면 모두 되돌아간다.
- 보냄이나 확인 완료인 0원 아닌 분담금이 있는 모임은 삭제할 수 없고 409(`GATHERING_SHARES_SENT`)다. 분담금을 먼저 미입금으로 되돌려야 한다.
- 삭제한 모임의 모임 페어링은 선택 신호로 남기지 않는다. 이미 지웠거나 없는 모임은 204이고, 모임장이 아니면 403이다. 성공하면 204다.

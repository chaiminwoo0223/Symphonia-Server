# 인프라 결정 기록

dev 인프라의 근거와 이력을 둔다. 현재 규칙은 `architecture` 스킬의 `infra.md`가 단일 소스다.

**(2026-11-29 결정, 이슈 #195)**: 앱 VM은 `e2-small`과 swap 4GB를 쓰고 DB만 Cloud SQL `db-f1-micro`로 분리한다. 비용을 줄이기 위해서다. `e2-medium`은 서울 리전의 월 비용이 약 두 배라 택하지 않았다. DB를 별도 VM의 컨테이너로 두는 안은 백업과 복구를 직접 관리해야 해서 택하지 않았다. 로컬에서 CPU 2개로 잰 앱 메모리는 `MALLOC_ARENA_MAX=2`에서 시작 직후 341MiB, 부하 중 680MiB였다. 설정하지 않으면 상한 768MiB에 닿아 swap했다. VM에서 swap 입출력이 계속되면 `e2-medium`으로 올린다.

**(2026-11-29 결정, 이슈 #195)**: Cloud SQL은 공인 IP와 허용 목록, `verify-ca`로 접속한다. 사설 IP 연결은 DB를 지운 뒤에도 VPC 피어링 삭제가 실패한다는 보고가 있어 택하지 않았다. Auth Proxy는 작은 VM의 메모리를 더 써서 택하지 않았다.

**(2026-11-29 결정, 이슈 #195)**: Terraform 상태를 세 모듈로 나누고 일시 중지, 삭제, 완전 철거의 세 단계를 둔다. 인프라를 쉽게 내리면서 잔여물을 남기지 않기 위해서다. DB와 고정 IP를 영구히 지우지 못하게 하는 안은 완전한 정리를 막아 택하지 않았다. 대신 DB 삭제 보호를 켜고 `teardown.sh`만 확인 입력 뒤에 해제한다.

**(2026-11-29 결정, 이슈 #195)**: 잔여물을 줄이려고 DB 자동 백업과 삭제 후 백업 보존을 끄고, 상태 버킷의 soft delete를 끄며, SSH 키에 1시간 만료를 둔다. DB가 손상되면 직접 받은 덤프로만 복구할 수 있다. 보존해야 할 사용자 데이터가 생기면 자동 백업을 다시 정한다. GCP 감사 로그, 결제 내역, 인증서 투명성 로그는 지울 수 없다.

**(2026-11-29 결정, 이슈 #195)**: 비밀값은 Secret Manager에 두고 VM이 직접 읽는다. DB 비밀번호는 `password_wo`로 보낸다. 값을 Terraform 변수나 리소스로 관리하는 안은 상태에 평문이 남아 택하지 않았다.

**(2026-11-29 결정, 이슈 #195)**: API는 `mariajou.duckdns.org`와 Caddy의 HTTPS로 제공한다. 웹이 HTTPS라서 HTTP API는 브라우저가 차단한다. 무료 도메인이라 가용성을 DuckDNS에 의존하므로, 운영 환경을 만들 때 도메인을 다시 정한다.
